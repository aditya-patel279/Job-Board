Your Roadmap
Modern E2E Testing
End-to-End (E2E) testing means testing the entire application flow from start to finish. In HireBoard, this means starting at the landing page, logging in, and verifying you reach the dashboard—just like a real user.

Playwright is Microsoft's answer to flaky tests. It is built to be "evergreen," meaning it handles modern web apps (React, Vue, etc.) effortlessly by automatically waiting for elements to appear before interacting with them.
Understanding the Config
Open playwright.config.ts. This is the global remote control for your tests. It tells Playwright:
  • Where your tests are: testDir: './tests/specs'
  • Your app's URL: baseURL: 'http://localhost:5173'
  • How many retries: retries: 1 (if a test fails once, try again)
The Basic Commands
You only need 4 core commands to write 90% of your tests:
  • 1
    page.goto(url) Navigates the browser to a page.
  • 2
    page.getByTestId(id) Finds an element using the custom data-testid we added for you.
  • 3
    locator.fill(text) / locator.click() Types into an input or clicks a button.
  • 4
    expect(locator).toBeVisible() The "Assertion" — checking that the result is what you expected.
Why POM?
If a button's ID changes and you have 20 tests using it, you don't want to edit 20 files. POM lets you define the "login button" once in a LoginPage class. All tests then use that class. Update it once, and every test is fixed instantly.
LoginPage.ts
export class LoginPage {
  get emailInput() { return this.page.getByTestId('email-input'); }
  async login(email, pass) { ... }
}
The Visual Debugger
Run npx playwright test --ui. This opens a visual dashboard where you can click through every step of a test and see exactly what the browser looked like at that moment. It's like time-travel for debugging!
Auto-recording with Codegen
Not sure how to write a test? Run npx playwright codegen localhost:5173. As you click around the app, Playwright will generate the code for you in a side window!

Beyond Code
CI/CD: We have GitHub Actions setup. Every time you push code, our tests run automatically on servers in the cloud to catch bugs before they reach users.

Visual Testing: toHaveScreenshot() takes a picture of your app and compares it to a baseline. If a single pixel changes (like a button moving slightly), it alerts you!
