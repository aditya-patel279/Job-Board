Modern E2E Testing
End-to-End (E2E) testing means testing the entire application flow from start to finish. In HireBoard, this means starting at the landing page, logging in, and verifying you reach the dashboard—just like a real user.

Playwright is Microsoft's answer to flaky tests. It is built to be "evergreen," meaning it handles modern web apps (React, Vue, etc.) effortlessly by automatically waiting for elements to appear before interacting with them. Imagine a robot that actually looks at the screen before clicking—that's Playwright.
Understanding the Config
Open playwright.config.ts in our repo. This is the global remote control for your tests. Notice these exact lines we set up for you:
playwright.config.ts
export default defineConfig({ // Where your tests live: testDir: './tests/specs', use: { // Setting the base URL means you can just type page.goto('/login') // instead of page.goto('http://localhost:5173/login') baseURL: 'http://localhost:5173', // Playwright will take a "trace" (a full snapshot of the test) on failures trace: 'on-first-retry' }, });
The Real Login Test
You only need 4 core commands to write 90% of your tests: goto, getByTestId, fill/click, and expect.

Look at this actual, runnable test. Copy this into a new file in tests/specs/ and run it with npx playwright test. Notice how we use the exact data-testid attributes from the HireBoard codebase!
tests/specs/login.spec.ts
import { test, expect } from '@playwright/test'; test('User can log in successfully', async ({ page }) => { // 1. Navigate to the page await page.goto('/login'); // 2. Locate inputs using the actual data-testids we put in Login.tsx await page.getByTestId('email-input').fill('applicant@test.com'); await page.getByTestId('password-input').fill('password123'); // 3. Click the submit button await page.getByTestId('login-submit').click(); // 4. Assert: verify they are redirected and the navbar updates await expect(page).toHaveURL(/dashboard/); await expect(page.getByTestId('nav-user-name')).toContainText('Alice Applicant'); });
Why POM?
If the login button's ID changes from login-submit to sign-in-submit, and you have 20 tests logging in, you do not want to edit 20 files. POM centralizes elements into "Page Classes".
tests/pages/LoginPage.ts
import { Page } from '@playwright/test'; export class LoginPage { constructor(public page: Page) {} // Define locators as getters get emailInput() { return this.page.getByTestId('email-input'); } get passwordInput() { return this.page.getByTestId('password-input'); } get submitBtn() { return this.page.getByTestId('login-submit'); } // Define common actions async login(email: string, pass: string) { await this.page.goto('/login'); await this.emailInput.fill(email); await this.passwordInput.fill(pass); await this.submitBtn.click(); } }
Now, look how clean your test file becomes! It reads like plain English:
tests/specs/login-clean.spec.ts
import { test, expect } from '@playwright/test'; import { LoginPage } from '../pages/LoginPage'; test('Clean POM Login Test', async ({ page }) => { const loginPage = new LoginPage(page); // One line executes the entire sequence! await loginPage.login('applicant@test.com', 'pwd123'); await expect(page).toHaveURL(/dashboard/); });
The Visual Debugger
Run npx playwright test --ui. This opens a visual dashboard where you can click through every step of a test and see exactly what the browser looked like at that moment. It's like time-travel for debugging!
Auto-recording with Codegen
Not sure how to write a test or what locator to use? Playwright can write the code for you!

Run npx playwright codegen localhost:5173. As you click around the app and interact with it, Playwright will generate the exact code for you in a side window. Try it!

Beyond Code
CI/CD: We have GitHub Actions setup. Every time you push code, our tests run automatically on servers in the cloud to catch bugs before they reach users.

Visual Testing: expect(page).toHaveScreenshot() takes a picture of your app and compares it to a baseline. If a single pixel changes (like a button moving slightly or CSS breaking), it alerts you!
